# 1.5.18 测试与已知边界

检查日期：2026-09-29。目标 PEAK **2.5.a / Build 25585932**，BepInEx **5.4.23.3**，Unity **6000.3.15f1**。

DLL SHA-256：`11E74DBA704FD8478E9D434DB792DF8D444EA9E327AF3EDCE89081FF1AD1D972`。

## 本次修复的依据

反馈者确认房主和队员均为 1.5.17；发生在新开局还是营火续玩尚不确定。本机没有反馈房间的双端日志，因此不能断言已重现那一局的完整事件顺序。

源码和隔离回放确认：旧版 `Receive` 仅在 `InRun == false` 时启用房主规则。如果队员已经以临时官方规则进入本局，之后收到天阶 20 配置只更新 `Selected`，不更新效果读取的 `Active`。模拟此顺序时，修复前天阶 13/20 的客户端效果开关未启用；修复后启用。另覆盖机场出发后仍收到 `running=false` 的顺序，避免清空刚接受的出发规则。

新版接收房主运行配置时核对并补齐实际规则；相同配置不重置计时。伤害继续由角色所属客户端通过原生状态系统处理，没有增加一轮房主伤害广播。额外龙卷风由房主生成网络对象，本来就可能在队员效果未启用时仍可见。

## 未验证与玩家复测

- **真实双客户端**：双方全装 1.5.18，新开局与营火续玩分别检查队员摔伤困倦、风雪/日照状态、状态倍率；晚加入、重连和房主迁移也需单独核对。
- **实际营火保存/恢复**：已测记录读写和接收分支，没有在真实地图完成往返。
- 迟到规则时 HUD 的实际显示、150 米雾的画面、所有地区天气物理和完整整合包冲突。
- 真实传输中的时延/丢包/回调顺序与整机性能；本版没有宣称解决所有联机问题。

复测时应在房主和队员日志中都看到 `Continued rules active`，以及天阶 20 对应的 `rules=2:20:...`。这表示该机器实际启用规则；机场选择回执或看到网络龙卷风不足以证明这一点。仍有异常时保留双端日志和最短复现过程，分享前移除个人路径、玩家/房间标识。
