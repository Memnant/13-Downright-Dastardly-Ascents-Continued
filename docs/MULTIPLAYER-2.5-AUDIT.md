# PEAK 2.5.a 联机排查与 1.5.19 天气修复

检查日期：2026-09-29。对比 Continued 1.5.16、1.5.17、1.5.18 源码，以及本机 PEAK 2.4.c 留存引用与 2.5.a 游戏程序集。

玩家反馈：故障队员仍显示“续作天阶 20”；后续确认睡眠惩罚已恢复，但森蕈风、暴风雪、下雨仍有不同步现象。没有取得故障那局的双端日志，不能把隔离回放当作已经重现该局。

## 版本差异

| 对比项 | 核查结果 |
|---|---|
| 1.5.16 → 1.5.17 | 规则同步、摔伤惩罚、天气调度源码没有改动。运行时代码变化集中于游戏版本、雾的七参数 AddStatus 适配、侧存档兼容；另更新原版雪暴资源的构建提取路径。 |
| 1.5.18 | 修复原有的规则晚到/机场回调时序缺口，并更新 HUD。该缺口在 1.5.16 已存在；不能仅凭其模拟用例证明它是 2.5 更新后反馈的唯一原因。 |
| PEAK 2.5.a 状态接口 | AddStatus 新增 ignoreSkeleton，SetAll 接收并传递该标志，重连恢复使用它防止骷髅伤势重复放大。1.5.17 已适配此接口。 |
| PEAK 2.5.a 重连 | CharacterSpawner 从对 UserId 再次取哈希改为直接查 UserId；跨区加入增加等待连接完成后再进房的步骤。可能影响进入流程的时序，但未证明是本局触发原因。 |
| 原生受伤与所有权 | Character.IsLocal、状态的 IsMine 检查及状态同步主体逻辑未改为“只由房主执行”。摔伤、风雪状态调用处的主要 IL 变化是 AddStatus 增加默认参数。 |
| 原生天气 | WindChillZone.HandleTime 和 RPCA_ToggleWind 的调度逻辑未变：房主用 RPC 通知开始/停止，当前阶段不保存在房间属性中。 |

官方更新说明包含重连/骷髅续玩修复、跨区加入修复及离开反重力球后的摔伤调整，没有宣布将这些天气或状态改成房主独占。[官方 Patch 2.5.a](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1844751498232435)

程序集比较检查了 9,762 / 9,791 个方法记录，原始差异 308 条。该数字包含生成的协程名称变化、默认参数变化和引用副本的公开化辅助类型，**不是 308 个兼容性问题**。后续对涉及的具体调用链作了反编译对照。

## 本次确认的两个时序缺口

### 1. 原生天气没有可补取的阶段

此前只有模组在无雪山地图中额外生成的雪暴使用房间阶段记录。地图自带森蕈风、雪山雪暴和雨仍用原生 RPC。

隔离回放的顺序是：队员缺少天气缓冲记录 → 原生开始天气 RPC 被缓冲补丁抑制 → 之后收到已过期的缓冲记录 → 队员解除等待，但原生风暴仍关闭，直到后续开始消息。这在已发布的 1.5.17 和 1.5.18 DLL 中均可复现。它能解释漏掉一轮原生天气；不证明所有实际天气差异都来自同一个顺序。

1.5.19 给三个原生天气各保存一个带 RunId 的房间阶段，包含开始时刻、持续时间、风向和开关。客户端读取当前记录，而不是自行抽取计时或等待下一条开始 RPC。原生旧 RPC 不再覆盖天阶 20 的阶段。晚加入/重连的风力渐入、曲线进度也按同一时钟补齐。仅阶段切换发布数据，逐帧读取复用缓存。

### 2. 加载途中接替房主

旧版在接替者仍停留菜单、尚未收到出发 RPC 时，可能未启用本局规则，却将自己的 `InRun=false` 发布回正在游戏的房间。已在旧 DLL 的完整接管回调路径中模拟复现。

1.5.19 在该接管边界先继承房间中正在运行的配置，再发布状态；新回归调用实际接管回调，并核对不会把房间改成未开局。此时旧菜单的基础天阶尚未更新，不用它覆盖已由原房主确认的本局配置。

## 保留的参数与范围

- 森蕈风、原生雪暴、下雨各自独立计时，允许交替或重叠。
- 风/雪正常停歇仍为 30–90 秒；天阶 20 雾沼雪暴停歇仍为 60–120 秒。
- 原生天气持续时间、下雨间隔仍读取地图组件的原参数；没有给雨套用雪暴的范围。
- 开局和原生续玩后 30 秒天气缓冲、最后区域禁用范围、保护区、地区强度及睡眠/伤害倍率保留。
- 官方及低于 20 阶的原生天气流程保留；单独强制开启 20 阶采用相同同步方式。
- 1.5.18 的睡眠惩罚修复保留，不增加房主向队员重复发送伤害。

## 其他模组的检查

本机整合包中 SaveMod 的加载标志会拦截 AddStatus，加载或续玩保护期间会跳过 CheckFallDamage；So Fly 也能按自己的飞行状态跳过 CheckFallDamage。这是反编译可见的作用范围，**尚未证明故障队伍启用了这些状态，也未将它们认定为本次根因**。没有修改或禁用这些模组。

## 验证边界

分别加载已发布的 1.5.17、1.5.18 DLL，在同样的合成房主/队员角色下执行原生 CheckFallDamage → AddStatus，比较实际状态数组。两种角色均有相同睡眠结果，寒冷、炎热、困倦、中毒、孢子倍率也相同，远端 SetAll 没有再次放大。这说明不存在所有非房主都必然失效的简单分支，不代表已复现真实游戏的落地、网络和整合包环境。

1.5.19 完成编译、接口解析及隔离组件回归。新增三种天气的晚加入、重连、旧 RPC、阶段结束、接管、错误 RunId/坏数据和低阶回归。详细结果见 [TESTING.md](TESTING.md)。真实双客户端、实际画面/受力、真实营火往返仍标为未验证。

复测时全员使用同一 1.5.19 DLL，比较同一地点的天气开始/停止和方向。日志每个原生天气阶段各记录一次 `Continued weather phase`；双方的类型、clock、duration、direction 应一致。此日志不包含玩家、房间或 Steam 标识。
